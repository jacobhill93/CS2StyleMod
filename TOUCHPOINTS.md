# Touchpoints

Inventory of game internals each `GameAdapters/` adapter depends on. Updated
whenever an adapter is added or re-verified against a new game version. See
"Patch-day workflow" in [ARCHITECTURE.md](ARCHITECTURE.md).

| `CustomZones/CustomZoneBuildRequestSystem.cs` | CustomZones | `Game.Prefabs.PrefabSystem.OnUpdate` (drives `SystemUpdatePhase.PrefabUpdate`), `Game.Serialization.LoadGameSystem` (dispatches `OnGameLoaded`), `Game.Common.SystemOrder` (registration order within `MainLoop`), `Game.Common.PrepareCleanUpSystem`/`CleanUpSystem` (strip `Created`/`Updated` every frame) | **Root cause found (2026-10-08)**, see DECISIONS.md "A runtime-cloned prefab is only visible to init systems for one frame": `Created`/`Updated` live for exactly one frame, and `LoadGameSystem` (which dispatches `OnGameLoaded`) is registered *after* `PrefabSystem` in the same `MainLoop` phase - so a clone added from `OnGameLoaded` always misses that frame's one `PrefabUpdate` pass and gets its tags stripped before the next one. Fix: this system registers `UpdateBefore<_, PrefabSystem>(MainLoop)` (same registration DillonN/specialized-industrial-zones uses) and only ever calls `CustomZoneBuilder.BuildOrRebuild` from its own `OnUpdate`, via a pending-request queue (a `CustomZoneDefinition` + its resolved `Collection`s) any caller can enqueue into from anywhere. Supersedes and replaces the deleted `ManualPrefabInitializationWorkaround.cs`, which worked around the *symptoms* (missing geometry/`SubMesh`/`SubObject`/`BuildingSpawnGroupData`, manual `ZoneSystem` registry/color reflection) without knowing the cause. | **In-game confirmed**: identical results to the old workaround (zone gets a real `ZoneType` index, correct color/paint, building geometry/`SubMesh`/`SubObject`/`BuildingSpawnGroupData` all populated by the real systems) across a single-building experiment, the full ~416-building production path, and the rebuild (additive-clone/retire) path, zero manual reinitialization, Steam build 25127643, 2026-10-08 |
| `CustomZones/GameAdapters/GameBuildingCatalog.cs` | CustomZones | `Game.Prefabs.SpawnableBuildingData`, `Game.Prefabs.SignatureBuildingData`, `Game.Prefabs.BuildingData.m_LotSize`, `Game.Buildings.PropertyUtils.GetZoneDensity`, `Game.Zones.AreaType`, `Game.Prefabs.PrefabSystem.TryGetPrefab(Entity, out T)`, `Game.Prefabs.AssetPackElement`/`AssetPackPrefab`, `Game.Prefabs.UIObject.m_Icon` | Real `Core.IBuildingCatalog`. Finds buildings by iterating an `EntityQuery` + matching `PrefabBase.name`, not `TryGetPrefab(PrefabID, out _)` - that overload's equality includes a content hash from the prefab's asset GUID, unknowable from a name alone, so it would never match. The `AreaType`/`IsOffice`/`ZoneDensity` → `Core.ZoneType` mapping mirrors ZoneOrganizer's own `IndexZones` categorization, not an assumption invented here. Excludes Signature buildings (`SignatureBuildingData` present) - they pass the `SpawnableBuildingData` query but are one-per-city landmarks, not regular growables; see DECISIONS.md. Also exposes `FindBuildingsByNamePrefix`, used by `CustomZoneBuilder`'s rebuild path to find what it already cloned for a zone, `GetAllBuildings`/`BuildingBrowserEntry` for the building-picker UI, whose `ResolveAssetPackIds` resolves every building's `AssetPackElement` buffer to its `AssetPackPrefab` name(s), falling back to a synthetic `"Vanilla"`/`"Vanilla (North America)"`/`"Vanilla (Europe)"` when that buffer is empty - see DECISIONS.md "Interaction between themes and the EU/NA theme setting and asset packs" for how this was verified - and `ResolveIconPath` (`BuildingBrowserEntry.IconPath`, UI overhaul Phase 4c), which reads `UIObject.m_Icon` per building: empty for most vanilla buildings (that field is normally a zone/category icon, not per-building), but Asset Icon Library writes a real `coui://ail/...` thumbnail URL into this same field for buildings it covers - see DECISIONS.md "Phase 4c implemented". **Known incomplete**: `BuildingCandidate.AssetPackId` (the separate `Resolve(VanillaSelectorEntry)` path, not the picker) is always `null` - asset-pack-filtered `VanillaSelectorEntry`s currently match nothing; not yet wired to the same `AssetPackElement` lookup `GetAllBuildings` now uses. | **In-game confirmed**: resolves ~416 buildings correctly (12 Signature buildings now correctly excluded, not just failing to clone) via `CustomZoneBuilder` with real `Collection` data; `GetAllBuildings`/`ResolveAssetPackIds` confirmed against 3962 buildings with Bridges & Ports, the China Content Creator Pack, and the community-made Detroit Bungalow Pack all installed - 6 distinct pack ids, zero buildings with none, Steam build 25127643, 2026-10-08. `ResolveIconPath`/`m_Icon`: **confirmed in-game with AIL actually installed (2026-10-12)** - most buildings show real AIL thumbnails, so AIL's write lands before our one-time `OnGameLoaded` read despite mod execution order between the two not being controlled. One real gap found: NA Old Town assets show no icon - believed to be AIL's own coverage gap for that pack, not a timing issue, since other buildings work fine - see DECISIONS.md. |
| `CustomZones/GameAdapters/GameZonePrefabResolver.cs` | CustomZones | `Game.Prefabs.ZoneData`, `Game.Prefabs.ZonePropertiesData`, `Game.Prefabs.PrefabSystem.TryGetPrefab(Entity, out T)` | Resolves `ZonePrefab`s two ways: a vanilla zone matching a `Core.ZoneType` category (reuses `GameBuildingCatalog.TryMapToCoreZoneType`, made `internal` rather than duplicated), or an already-registered zone by exact name (same name-match technique as `GameBuildingCatalog.TryGetBuildingPrefab`) - the second is what lets `CustomZoneBuilder` find a zone it already built, for rebuild. | **In-game confirmed**: both lookups work correctly across the build and rebuild paths, Steam build 25127643, 2026-10-08 |
