# Touchpoints

Inventory of game internals each `GameAdapters/` adapter depends on. Updated
whenever an adapter is added or re-verified against a new game version. See
"Patch-day workflow" in [ARCHITECTURE.md](ARCHITECTURE.md).

| `CustomZones/GameAdapters/ManualPrefabInitializationWorkaround.cs` | CustomZones | `Game.Prefabs.PrefabInitializeSystem`, `Game.Prefabs.ZoneSystem` (private `m_ZonePrefabs`, private `UpdateZoneColors()`), `Game.Prefabs.ObjectInitializeSystem`, `Game.Objects.SubObjectSystem`, `ComponentBase.Initialize`/`LateInitialize`, `Game.Common.UpdateSystem.Update(SystemUpdatePhase)` | **Root cause still unknown** (see DECISIONS.md): a prefab added via `PrefabSystem.AddPrefab` after initial load never gets processed by any `Created`-tag-keyed system - not `PrefabInitializeSystem`, not `ZoneSystem`, not `ObjectInitializeSystem`. Confirmed this isn't a timing, phase-registration, or zone-type issue (tried immediate vs. deferred, `PrefabUpdate` vs. `MainLoop`, Residential vs. Industrial - identical failure every time), and confirmed calling `UpdateSystem.Update(SystemUpdatePhase.PrefabUpdate)` manually, directly, does not trigger it either, despite `PrefabSystem.OnUpdate()` calling that exact line unconditionally every tick. Workaround, in order: copy `ObjectGeometryData`/`BuildingData` plus every `DynamicBuffer<T>` the template has (discovered generically via `Archetype.GetComponentTypes()`, not hand-named - found `SubMesh`/`SubObject` gaps this way) straight onto the clone; call `ComponentBase.Initialize`/`LateInitialize` directly on every attached component (covers everything a component sets itself, and runs after so clone-specific values override the template mirror); reflect into `ZoneSystem`'s private zone registry and color-array refresh (bespoke to that system, not a component method). | **In-game confirmed working** across the full ~416-building vanilla selector plus explicit assets, not just the single hand-picked building from the first pass: rendering, sub-objects (fences/chimneys/etc.), and fence-coverage-depends-on-geometry-copy-order all fixed, Steam build 25127643, 2026-10-08 |
| `CustomZones/GameAdapters/GameBuildingCatalog.cs` | CustomZones | `Game.Prefabs.SpawnableBuildingData`, `Game.Prefabs.SignatureBuildingData`, `Game.Prefabs.BuildingData.m_LotSize`, `Game.Buildings.PropertyUtils.GetZoneDensity`, `Game.Zones.AreaType`, `Game.Prefabs.PrefabSystem.TryGetPrefab(Entity, out T)` | Real `Core.IBuildingCatalog`.
